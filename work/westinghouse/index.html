Westinghouse Electric · Software IV&V intern · Summer 2025

Verification of nuclear safety software

In Westinghouse's Independent Verification & Validation department, I checked changes to the software that protects nuclear plants: diffing the code, marking every difference, and tracing each one back to its requirement.

Project names, plant details and system specifics are confidential to Westinghouse, so this page describes the work in general terms.

What IV&V is

Independent Verification & Validation checks that safety software meets its requirements and does its job correctly and reliably. Verification asks "are we building it right?" Validation asks "are we building the right thing?" The department is kept separate from the engineers who write the code, both financially and in who it reports to, so the review stays unbiased.

What I did

Plant protection systems run the same logic on several redundant processors, so if one fails, the others still protect the plant. My work was making sure those copies, and each new release, were exactly what they were supposed to be.

  • Code diffs across redundant processors. Compared the code running on each redundant channel side by side to confirm the copies matched where they should and differed only where the design said they could.
  • Diffs between releases. Compared old and new versions of the code to find every change in a new release.
  • Greenlining. Marked up every difference found, one by one, so nothing went unreviewed.
  • Tracing changes to requirements. Traced each change back to the software requirements and design documents to confirm it was intended, documented and correct. A change with no requirement behind it is a finding.
  • Checking that review comments were fixed. Confirmed that changes requested in earlier review rounds actually appeared in the next document revision.

What I learned

Safety software is slow on purpose. When a failure can hurt people, every change needs a written reason and a second set of eyes, and "it probably works" isn't an answer. That discipline stuck with me. It's the same instinct behind building AI systems that say "I don't know" instead of guessing, and behind tracking whether a release actually delivered what it promised.

I also got fast at the work. By the end, diffing and greenlining had a real rhythm to it. When another intern joined a week after me, I helped get him set up, and teaching it made me understand it better.
