BasePlate, a LEGO resale valuation tool

A tool I built for my LEGO reselling. Give it a set, a buy price and a condition, and it values the set in every condition, compares the net after each platform's fees, and returns BUY or PASS with the reasoning written out.

5 conditionssealed to incomplete, valued at once
5 platformsnet after each one's real fees
583 testsacross 156 suites, all passing

What it does

  • Valuation. Market value for a set in every condition at once: sealed, open box, used with box, used without box, and incomplete. Plus its 12-month trend and a graded forecast.
  • BUY / PASS verdict. Given a buy price and condition, it picks the best play (flip it sealed, resell it used, or part it out), works out the net after fees, and only says BUY if the margin clears the threshold, 25% by default. Every verdict comes with its reasoning.
  • Net after fees, per platform. eBay, Mercari, Facebook (local and shipped) and BrickLink, each with its published fee formula, side by side.
  • Retiring board. Sets about to leave production, the window resellers watch most closely. Most retirement dates are only known to the month, and it labels them that way.
  • Minifigures. Per-figure values, plus a flag for sets where the figures carry most of the value.

Two rules I built it around

Honesty over completeness

This tool informs real money decisions, so it never shows a made-up, estimated or stale number as if it were real. Missing data says "not valued yet," never $0.00. Estimates are flagged, stale values get a banner, and anything from mock data is labelled MOCK. A blank is better than a confident guess.

Don't burn the API budget

The main pricing source allows 100 requests a day. One page of search results could burn that if every view fetched prices. So browsing, sorting and filtering only read from a local cache, and only an explicit "Value this set" or "Refresh" click spends a request. Every outbound call is logged and shown in a quota meter, and the test suite checks that reading the cache never touches the network.

How it's built

The core is pure logic with no network or database code in it. It defines interfaces for everything it needs (prices, part-out values, the set catalog, storage, the clock), and one wiring file decides what backs each one, real or mock. That's the ports-and-adapters pattern. It's why the engine runs the same from the web app or the command line, and why swapping a data source doesn't touch the valuation logic.

Status

Working: valuation, verdicts, per-platform nets, set lookup, watchlist, trending, the retiring board, set detail pages and minifigure values.

Still mock: part-out value. It needs BrickLink's price data, and BrickLink only opens its API to verified sellers. Until then it's labelled MOCK everywhere.

Next, when I pick it back up: an inventory and profit dashboard, real part-out with an optimizer, and a sourcing tool for finding the cheapest parts to rebuild a set.
